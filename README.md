# GR86 Watch

トヨタ GR86・スバル BRZ(GR86の兄弟車)・マツダ ロードスター(MX-5 Miata)、そして旧型
トヨタ86(GT86/FT86)に関する情報を1か所に集約するモニタリングダッシュボード。GitHub Actions
で30分おきに自動的にデータを収集し、GitHub Pagesで公開する。「GR Corolla Watch」と同じ設計
思想(公式APIキー不使用・GitHub Pages + Actions cron)を踏襲しつつ、車種別フィルタ・バイリン
ガル(日本語/英語)UI・モータースポーツ競技フォーマット解説・グレード別ライバル車スペック
比較を新たに追加している。トヨタ86(GT86/FT86)は生産終了モデルのため、YouTube・SNS話題
セクション限定の対象車両として扱っている(公式リリース/メディア評価/クレーム/イベント/
モータースポーツの対象外)。

GitHub Pagesは静的サイトのみでサーバー側処理ができないため、アクセスの都度リアルタイムに
取得することはできない(Google News/YouTube/GR Cup公式サイト等はCORS制限でブラウザから直接
取得できず、アクセスごとに実スクレイピングを走らせるとレート制限で機能停止するリスクが
高い)。そのため「アクセスの都度更新」の実質的な代替として、30分おきの自動更新を採用している。

**公開ページ:** `https://naosaka-76.github.io/GR86/` (Settings > Pages で GitHub Actions を
ソースに設定後、`update-dashboard` ワークフローの実行により自動的に公開される)

## ダッシュボードの構成(上から順に)

1. **公式リリース & メディア評価**(統合1パネル) — GR86/GR86 Cup Edition・BRZ・ロードスター
   (MX-5)の公式発表とメディアレビューを1つのフィードに統合。項目ごとに「公式」/「メディア
   評価」の種別バッジ付き。パネル内に **すべて/GR86/BRZ/ロードスター** の4ボタンフィルタが
   あり、車種別に絞り込める。
2. **YouTube** — GR86・トヨタ86(GT86/FT86)・BRZ・ロードスターの4車種。トレンド(人気)/
   最新のタブ切替、グローバル/日本語のサブグループ表示、加えて同じ すべて/GR86/BRZ/ロード
   スター の4ボタンフィルタ(トヨタ86はGR86ボタンに統合。バッジ表示は「トヨタ86」のまま
   個別に残る)。
3. **SNSでの話題** — 同4車種、同じタブ+フィルタのUI。X/Facebook/Instagramの投稿本体は取得
   できないため、ニュース・ブログでの言及を代替指標として使用。
4. **お客様の声・クレーム関連情報** — GR86・BRZ・ロードスターの3車種(トヨタ86は対象外)。
   同じトレンド/最新タブ + すべて/GR86/BRZ/ロードスターフィルタのUI。
5. **世界各地のイベント情報** — オーナーズミーティング・試乗会・モーターショー出展など
   「人が集まる」イベントのみ(プレスリリース記事は除外)。
6. **モータースポーツ** — 下記「モータースポーツ(地域別)」参照。トピックス速報 + 各シリーズの
   競技フォーマット解説(静的データ)+ グレード別ライバル車スペック比較(静的データ、日本/
   米国/豪州)。

全セクション(公式リリース・静的カタログを除く)に、見出し文からの簡易センチメント判定
(ポジティブ/ネガティブ)を付与している(英語: VADER、日本語: 自動車レビュー向け手作り
極性辞書)。「トレンド」タブ以外は公開日時の新しい順に並び替えている。

日本・米国・欧州・豪州の4地域すべてでクエリを組んでいるのは公式リリース/メディア評価/SNS
話題/クレーム系セクション(GR86・BRZ・ロードスターの3車種)。各記事/動画には車種タグ
(GR86 / トヨタ86 / BRZ / ロードスター(MX-5))が付く。**車種フィルタは2026年9月にヘッダー
から各パネル内へ移動**し、パネルごとに独立した「すべて/GR86/BRZ/ロードスター」の4ボタンで
絞り込む方式にした(以前はヘッダー1箇所の共通フィルタだった)。この4ボタン方式では、旧型
トヨタ86(GT86/FT86)はGR86ボタンに統合されている(バッジ表示自体は元の車種名のまま)。

## 既知の制約

- **30分おきはGitHub Actionsのcronによる近似値**: 実行が数分遅れることがある(GitHub公式が
  明記している既知の挙動)。GR Cup公式サイトへは1回の実行で数ページを取得するため、更新頻度を
  さらに上げる場合は先方サイトへの負荷にも配慮すること。
- **公式API未使用**: YouTube Data API・X API・Facebook/Instagram Graph API のキーは未設定。
  すべて無料の公開エンドポイント(Google News RSS、YouTube検索ページ、各シリーズ公式サイトの
  標準スクレイピング)をベストエフォートで利用しているため、件数の正確性・網羅性は公式APIに
  劣る。
- **X/Facebook/Instagramの投稿本体は含まれない**: ニュース/ブログでの言及を代替指標として
  表示している。
- **クレーム情報は社内システム未連携**: 公開されている報道のみを集約した簡易モニタリング。
- **参戦チーム/ドライバー名簿セクションは廃止**: 以前はGR Cup北米の参戦チーム名簿パネルを
  設けていたが、2026年8月のリクエストにより削除した。GR Cup北米のスケジュール/ランキング
  自体は引き続きモータースポーツセクション内に実データで表示している。
- **モータースポーツの各カードでスケジュール/ランキングは折りたたみ表示(初期状態は閉じている)**:
  実データを持つカードが縦に長くなりすぎないよう、`<details>/<summary>`によるトグル表示にして
  いる。
- **YouTube検索スクレイピングの脆弱性**: YouTube側のページ構造変更により取得に失敗する可能性が
  ある。動画ごとの概要欄プレビューは、GitHub Actionsの共有IPからの連続アクセスでGoogle側の
  ボット対策(HTTP 429)にほぼ確実に引っかかるため実装していない(検索結果ページ自体のスクレイ
  ピングは問題なく動作する)。
- **モータースポーツの実データ化はGR Cup(北米)とTGR GR86/BRZ Cup(日本)のスケジュールのみ**:
  - **北米(Toyota GR Cup)**: grcupseries.comがTC America(tcamerica.us、GR Corolla Watchで
    確認済み)と同一のCMS基盤(同じ`filter_season_id`/`filter_standing_type`セレクタ、同じ
    `<table class="table standing">`マークアップ)を使っていたため、その解析ロジックを流用して
    実データのスケジュール/チームズ・ドライバーズランキングを取得できている。
  - **日本(TGR GR86/BRZ Cup)**: 公式カレンダーページ(`/jp/86brz/calendar/{year}/`)が静的HTMLで
    あることを確認し、年間スケジュールを実データ化した。ただし順位表(ランキング)ページは
    PDFへのリンクのみでHTML表が存在しないため、ドライバー氏名の文字化けリスクを避け順位の
    スクレイピングは行っていない(ニュース集約 + 公式PDFへのリンクのみ)。
  - **オーストラリア(GR Cup Australia)**: 公式サイトがボット対策等でHTTP 403を返しスクレイ
    ピング不可。サードパーティ(supercars.com)にセッション単位の結果ページはあるが、シーズン
    通算のポイントランキングは見当たらずURL命名規則も不安定なため、誤ったデータ欠落リスクを
    避けスクレイピングは見送っている。ニュース集約 + 検索リンクのみ。
  - **欧州**: GR86/BRZの現行ワンメイク選手権・専用クラスは確認できなかったが、旧型GT86時代に
    ドイツ・ニュルブルクリンクのVLN(現NLS)耐久シリーズ内に存在した「TMG GT86 Cup」という
    専用クラスは公式発表で存在が確認できた(2013年開幕)。現行(2024〜2026年)NLSの公式クラス
    一覧には見当たらず、独立クラスとして現在も継続しているかは確認できないため、「現状不明の
    過去実績」として参考掲載している。
  - **Mazda MX-5 Cup(北米)**: mx-5cup.comはGR Cupと異なる基盤で運用されており、静的HTMLでの
    安定した取得ができなかった。ニュース集約 + 公式サイトへのリンクのみ。
- **イベント情報の正確な日程・開催地は本文まで解析できていない**: Google News RSSは見出し文
  のみで、リンク先はJavaScriptによるリダイレクトが必要なため記事本文を取得できない。参加を
  検討する場合は必ず元記事で日程・開催地を確認すること。
- **センチメント判定は見出し文のみの自動推定**: 記事本文・動画本編・コメント欄までは解析して
  いない。判定根拠語が1つ以下の場合は中立とする2語ゲート(英語のみ)により、単語1つで結論が
  引っ張られる誤判定を抑えているが、その分「弱い根拠1語のみ」のケースは中立寄りになりやすい。
  日本語の見出しでは、まれに車種名と無関係な語の一致で誤判定するケースがある(例: 車種名と
  文脈上無関係な固有名詞・略語がクエリにヒットするケース)。
- **グレード別価格比較は静的データ**: 手動調査した参考値であり、30分おきの自動収集対象外。
  日本・米国・オーストラリアの3市場を掲載(価格帯バーも3通貨分)。価格は為替・改良・在庫
  状況等で変動するため参考値として扱うこと。メーカー公式サイトで直接確認できなかった項目は
  「media」(報道ベース)と明示し、情報源間で差異がある項目はreference-onlyとして各グレード
  表内に明示している。米国はSubaru of America・Mazda USAの公式プレスリリースを直接確認
  できたため「official」、GR86米国仕様はトヨタ公式価格を引用する自動車メディア(Cars.com/
  CarBuzz)を採用したため「media」としている。
- **「BRZ」「ロードスター」は一般名詞と衝突しうる**: 曖昧さを避けるため必ずメーカー名
  (スバル/Subaru, マツダ/Mazda)とのAND検索にしているが、それでも無関係な記事が稀に混入する
  ことがある(見出しベースの簡易フィルタの限界)。

より高精度な情報が必要な場合は、各社の公式APIキー(YouTube Data API v3, X API, Facebook Graph
API)を取得し、`scripts/sources/` 配下の該当モジュールを差し替えることで精度を向上できる。

## 構成

```
scripts/
  fetch_data.py           # 全ソースを集約し site/data/latest.json を生成
  sources/
    common.py              # RSS取得・数値/日時パース等の共通処理
    sentiment.py            # 見出し文からのポジティブ/ネガティブ推定
    vehicles.py              # GR86/トヨタ86/BRZ/ロードスター(MX-5) 共通のクエリ設定(地域×車種)
    official_news.py         # GR86/BRZ/MX-5のみ(トヨタ86は対象外)
    media_reviews.py         # GR86/BRZ/MX-5のみ(トヨタ86は対象外)
    social_buzz.py            # トヨタ86を含む4車種対象
    complaints.py             # GR86/BRZ/MX-5のみ(トヨタ86は対象外)
    events.py
    youtube.py                 # トヨタ86を含む4車種対象
    motorsports.py              # REGIONS -> series のネスト構造(北米/日本・アジア/豪州/欧州/MX-5 Cup)
    schedule.py                  # GR Cup(北米)・TGR GR86/BRZ Cup(日本)の年間レース日程(実データ)
    standings.py                  # GR Cup(北米)公式サイトのチームズ/ドライバーズランキング(実データ)
site/
  index.html / style.css / app.js   # ダッシュボード本体(静的サイト、日英バイリンガルUI)
  data/latest.json                    # 自動生成される最新データ(コミット対象外)
  data/rivals.json                     # グレード別価格比較(手動収集の静的データ、コミット対象)
  data/motorsports_formats.json        # 各シリーズの競技フォーマット解説(手動収集の静的データ)
.github/workflows/update-dashboard.yml  # 30分おきの自動更新 + GitHub Pagesデプロイ
```

## ローカルでの動作確認

```bash
cd scripts
pip install -r requirements.txt
python fetch_data.py          # site/data/latest.json を生成(実行に1〜2分程度かかる)
cd ../site
python3 -m http.server 8000   # http://localhost:8000 で確認
```

## GitHub Pagesの有効化(初回のみ)

リポジトリの Settings > Pages > Build and deployment > Source を **GitHub Actions** に設定
する。設定後、`update-dashboard` ワークフローの実行(スケジュールまたは手動の
`workflow_dispatch`)によって自動的に公開される。
