# GR86 Watch

トヨタ GR86・スバル BRZ(GR86の兄弟車)・マツダ ロードスター(MX-5 Miata)に関する情報を1か所に
集約するモニタリングダッシュボード。GitHub Actionsで30分おきに自動的にデータを収集し、
GitHub Pagesで公開する。「GR Corolla Watch」と同じ設計思想(公式APIキー不使用・GitHub Pages +
Actions cron)を踏襲しつつ、3車種横断の車種別フィルタ・バイリンガル(日本語/英語)UI・
GR Cup参戦チーム名簿・ライバル車スペック比較を新たに追加している。

GitHub Pagesは静的サイトのみでサーバー側処理ができないため、アクセスの都度リアルタイムに
取得することはできない(Google News/YouTube/GR Cup公式サイト等はCORS制限でブラウザから直接
取得できず、アクセスごとに実スクレイピングを走らせるとレート制限で機能停止するリスクが
高い)。そのため「アクセスの都度更新」の実質的な代替として、30分おきの自動更新を採用している。

**公開ページ:** `https://naosaka-76.github.io/GR86/` (Settings > Pages で GitHub Actions を
ソースに設定後、`update-dashboard` ワークフローの実行により自動的に公開される)

全セクション(公式リリース・静的カタログを除く)に、見出し文からの簡易センチメント判定
(ポジティブ/ネガティブ)を付与している(英語: VADER、日本語: 自動車レビュー向け手作り
極性辞書)。「人気動画」以外は公開日時の新しい順に並び替えている。

各記事/動画には車種タグ(GR86 / BRZ / ロードスター(MX-5))が付き、ヘッダー下の車種フィルタで
横断的に絞り込める。GR86とBRZは兄弟車として同じニュースフィード内に統合し、ロードスター
(MX-5)も同水準の独立した追跡対象車両として扱っている(ライバル車カタログには比較対象として
別途ロードスター/MX-5も掲載しており、これは「追跡車両としてのMX-5」とは別軸の意図的な重複)。

## 既知の制約

- **30分おきはGitHub Actionsのcronによる近似値**: 実行が数分遅れることがある(GitHub公式が
  明記している既知の挙動)。GR Cup公式サイトへは1回の実行で数ページを取得するため、更新頻度を
  さらに上げる場合は先方サイトへの負荷にも配慮すること。
- **公式API未使用**: YouTube Data API・X API・Facebook Graph API のキーは未設定。すべて無料の
  公開エンドポイント(Google News RSS、YouTube検索ページ、grcupseries.com標準スクレイピング)を
  ベストエフォートで利用しているため、件数の正確性・網羅性は公式APIに劣る。
- **X/Facebookの投稿本体は含まれない**: ニュース/ブログでの言及を代替指標として表示している。
- **クレーム情報は社内システム未連携**: 公開されている報道のみを集約した簡易モニタリング。
- **YouTube検索スクレイピングの脆弱性**: YouTube側のページ構造変更により取得に失敗する可能性が
  ある。動画ごとの概要欄プレビューは、GitHub Actionsの共有IPからの連続アクセスでGoogle側の
  ボット対策(HTTP 429)にほぼ確実に引っかかるため実装していない(検索結果ページ自体のスクレイ
  ピングは問題なく動作する)。
- **モータースポーツの実データ化はGR Cup(北米)のみ**: grcupseries.comがTC America
  (tcamerica.us、GR Corolla Watchで確認済み)と同一のCMS基盤(同じ`filter_season_id`/
  `filter_standing_type`セレクタ、同じ`<table class="table standing">`マークアップ)を使って
  いたため、その解析ロジックを流用して実データのスケジュール/チームズ・ドライバーズランキングを
  取得できている。それ以外:
  - **日本(TGR GR86/BRZ Cup)**: 公式概要ページは見つかったが、静的HTMLのスケジュール表/順位表
    ページを確認できなかった。ニュース集約 + 公式ページへのリンクのみ。
  - **オーストラリア(GR Cup Australia)**: 公式サイトがボット対策等でHTTP 403を返しスクレイ
    ピング不可。ニュース集約 + 検索リンクのみ。
  - **欧州**: 2026年8月時点でGR86の現行ワンメイク/プロダクションクラス選手権を確認できず、
    セクション自体を設けていない。
  - **Mazda MX-5 Cup(北米)**: mx-5cup.comはGR Cupと異なる基盤で運用されており、静的HTMLでの
    安定した取得ができなかった。ニュース集約 + 公式サイトへのリンクのみ(参戦チーム名簿も
    GR Cupのみ構築しており、MX-5 Cupの名簿までは対象外としている)。
- **GR Cup参戦チーム名簿の背景情報は一部web検索ベース**: チームの設立経緯・タイトル獲得歴などは
  公開情報からの手動調査であり、一次資料(公式リリース原文等)での全項目の裏取りまでは行って
  いない。順位/ポイント/エントリードライバー名は公式サイトの実データ。ラウンドをまたいだ表記
  ゆれのある同一人物名は統合せず、公式データのまま(重複があれば重複のまま)表示している。
- **イベント情報の正確な日程・開催地は本文まで解析できていない**: Google News RSSは見出し文
  のみで、リンク先はJavaScriptによるリダイレクトが必要なため記事本文を取得できない。参加を
  検討する場合は必ず元記事で日程・開催地を確認すること。
- **センチメント判定は見出し文のみの自動推定**: 記事本文・動画本編・コメント欄までは解析して
  いない。判定根拠語が1つ以下の場合は中立とする2語ゲート(英語のみ)により、単語1つで結論が
  引っ張られる誤判定を抑えているが、その分「弱い根拠1語のみ」のケースは中立寄りになりやすい。
  日本語の見出しでは、まれに車種名と無関係な語の一致で誤判定するケースがある(例: 車種名と
  文脈上無関係な固有名詞・略語がクエリにヒットするケース)。
- **ライバル車スペック・GR Cup参戦チーム背景は静的データ**: 手動調査した参考値であり、30分おき
  の自動収集対象外。価格・数値は年式・グレード・情報源により変動するため参考値として扱うこと。
  未確認/情報源により差がある数値は各カード内に明示している。
- **「BRZ」「ロードスター」は一般名詞と衝突しうる**: 曖昧さを避けるため必ずメーカー名
  (スバル/Subaru, マツダ/Mazda)とのAND検索にしているが、それでも無関係な記事が稀に混入する
  ことがある(見出しベースの簡易フィルタの限界)。

より高精度な情報が必要な場合は、各社の公式APIキー(YouTube Data API v3, X API, Facebook Graph
API)を取得し、`scripts/sources/` 配下の該当モジュールを差し替えることで精度を向上できる。

## 構成

```
scripts/
  fetch_data.py           # 全ソースを集約し site/data/latest.json を生成
  sources/
    common.py              # RSS取得・数値/日時パース等の共通処理
    sentiment.py            # 見出し文からのポジティブ/ネガティブ推定
    vehicles.py              # GR86/BRZ/ロードスター(MX-5) 共通のクエリ設定(地域×車種)
    official_news.py
    media_reviews.py
    social_buzz.py
    complaints.py
    events.py
    youtube.py
    motorsports.py           # REGIONS -> series のネスト構造(北米/日本・アジア/豪州/MX-5 Cup)
    schedule.py               # GR Cup公式サイトの年間レース日程(実データ)
    standings.py               # GR Cup公式サイトのチームズ/ドライバーズランキング(実データ)
    participant_roster.py       # GR Cup参戦チーム名簿(背景静的データ + 実データ順位/エントリー)
site/
  index.html / style.css / app.js   # ダッシュボード本体(静的サイト、日英バイリンガルUI)
  data/latest.json                    # 自動生成される最新データ(コミット対象外)
  data/rivals.json                     # ライバル車スペック比較(手動収集の静的データ、コミット対象)
.github/workflows/update-dashboard.yml  # 30分おきの自動更新 + GitHub Pagesデプロイ
```

## ローカルでの動作確認

```bash
cd scripts
pip install -r requirements.txt
python fetch_data.py          # site/data/latest.json を生成(実行に1〜2分程度かかる)
cd ../site
python3 -m http.server 8000   # http://localhost:8000 で確認
```

## GitHub Pagesの有効化(初回のみ)

リポジトリの Settings > Pages > Build and deployment > Source を **GitHub Actions** に設定
する。設定後、`update-dashboard` ワークフローの実行(スケジュールまたは手動の
`workflow_dispatch`)によって自動的に公開される。
